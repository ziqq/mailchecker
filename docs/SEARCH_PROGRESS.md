# Серверный поиск: 0.0.39

## Реализация

Поиск выполняется на сервере каждого поддержанного ящика. IndexedDB хранит уже полученные данные, не заменяет серверную историю и не запускает её предварительное скачивание. Регрессионные тесты IndexedDB и версия 0.0.38 закоммичены отдельно: `a56bac5`, с соавтором `ziqqineyo <a.a.ustinoff@yandex.ru>`.

Новый запрос `SEARCH` возвращает до 20 результатов на ящик и его отдельный статус. «Загрузить ещё» продолжает только незавершённые страницы. Ошибка содержит адрес ящика; повтор использует прежний курсор неудачной страницы, сохраняя успешные результаты. Одинаковые письма объединяются по ящику и ID. Смена запроса, папки или ящика отбрасывает запоздалые ответы. Подтверждённые read/pin/move накладываются поверх ответа, начатого до действия.

## Проверки

Постоянные тесты нового поиска до подтверждения основной реализации не менялись. Для принятия используется превью `?search=paged&searchError=work`: 45 серверных записей на каждый ящик и разовая ошибка одного из них. Эти данные создаются только внутри sandbox и не попадают в release.

- `npm run verify`: форматирование, ESLint, строгий TypeScript, **170 unit-тестов**, инварианты репозитория и упаковка `dist/mailchecker-0.0.39.zip` — успешно.
- `npm run test:sandbox -- --workers=4`: **88 браузерных сценариев** — успешно. В подготовке ранее принятого MV3-теста кеша исправлено пробуждение холодного worker обычной страницей настроек; проверки кеша сохранены. Первый массовый прогон выявил таймауты, итоговый полный прогон завершён успешно.
- Safari-сборка — успешно; запуск установленного Safari-расширения не проверялся.
- `npm audit --audit-level=high`: **0 уязвимостей**.
- Временная диагностика вне репозитория проверила продолжение Gmail, изоляцию запроса/хоста Graph, пропуски `Email/get` и серверный размер страницы JMAP, внутреннее смещение Яндекса, курсор/папку/токен Mail.ru. Это синтетическая проверка протокола, не подтверждение живой интеграции.
- В браузере проверен `app.html` при **1440×900, 780×600, 400×600, 390×844**: горизонтального переполнения нет. Частичная ошибка оставила 80 строк; повтор добавил недостающий ящик до 100; дальнейшие страницы дали 200 и 225 уникальных строк. На конце выдачи кнопка продолжения исчезла. Popup и mini дополнительно покрыты общим автоматическим набором.

На этапе 0.0.39 изменения поиска были оставлены в рабочем дереве для приёмки. После подтверждения реализации постоянные регрессионные тесты добавлены в 0.0.40; результаты ниже. Для Gmail владелец выбрал поиск через отдельное подключение Gmail API; мост к вкладке и новое разрешение `scripting` отложены.

Источник Mail.ru: фактически загруженный [bundle веб-клиента](https://imgs2.imgsmail.ru/octavius/ru_RU/bundles/js/app.88e472ea1e539086e7b3.js), метод `messages/search`, параметры `query`/`offset`/`limit`/`with_threads` и ответ `messages`/`found.count`.

## Приёмка и регрессионные тесты: 0.0.40

После подтверждения реализации добавлены постоянные проверки в `tests/providers.test.mjs`, `tests/background.test.mjs`, `tests/client.test.mjs` и `e2e/sandbox.spec.mjs`.

- Gmail API: передача запроса и непрозрачного токена, ограничение числа metadata-запросов, конец выдачи, истёкшая авторизация.
- Microsoft Graph: исходный запрос и непрозрачное продолжение, изоляция хоста/коллекции, повтор курсора, предел 1000 результатов, истёкшая авторизация.
- JMAP: RFC text-filter, позиции по ID `Email/query`, исчезнувшая запись `Email/get`, размер страницы меньше запрошенного при наличии серверного total, конец выдачи и авторизация.
- Яндекс: полный обход строк внутри lite-страницы, переход по фактической ссылке, порядок без выдуманных дат, допустимый алиас владельца, чужой ящик/запрос/URL, пустая выдача и выход из аккаунта.
- Mail.ru: курсоры и смещения, токен нужного адреса, `with_threads=false`, исходная папка/переписка, пустая выдача, некорректные ответы и авторизация.
- Браузерный Gmail: явная недоступность встроенного поиска без HTTP-запроса, моста или нового разрешения.
- Worker и store: частичные ошибки и повтор только неудачного ящика, границы входных данных, дубликаты, одинаковые ID разных ящиков, сохранение прочитанных/закреплённых флагов и действий поверх поздней страницы, смена запроса/папки/ящика и очистка.
- Браузер: первая страница с ошибкой одного ящика даёт 80 строк; повтор — 100; продолжения — 200 и 225 уникальных строк. Все пять поддержанных провайдеров дают по 45 результатов. Последняя страница убирает кнопку, пустой запрос возвращает входящие, пустая выдача показывает правильное сообщение. Проверены popup 780×600, mini 400×600, tab 1440×900, phone popup и tab 390×844.

`npm run verify`: **212 unit-тестов**, форматирование, ESLint, TypeScript, инварианты и упаковка — успешно. `npm run test:sandbox -- --workers=4`: **93 сценария**, включая native IndexedDB и MV3, — успешно. `npm run build:safari` — успешно. `npm audit --audit-level=high`: **0 уязвимостей**. `python3 scripts/package.py --verify dist/mailchecker-0.0.40.zip` — успешно.
